## 第 1 点：错峰起飞与速度调整的航班选择方式

> **说明**：错峰起飞和速度调整在**两个阶段均有使用**——阶段 1（FATA）同时优化所有关键航班，无需逐架选择；**阶段 2（贪心修复）** 按冲突贡献排名逐架选择。以下是阶段 2 的选择机制。

### 两阶段中的策略分布

| 阶段 | 优化方式 | 错峰起飞 | 速度调整 | 局部改航 |
|------|----------|:---:|:---:|:---:|
| 阶段 1（FATA） | 关键航班**同步**优化 | ✅ 主要使用 | ✅ 辅助 | ❌ |
| 阶段 2（贪心修复） | 按冲突排名**逐个**选择 | ✅ 优先尝试 | ✅ 延迟无效时尝试 | ✅ 最后手段 |
| 阶段 2（局部改航） | 冲突段遍历尝试 | ❌ | ❌ | ✅ 主要使用 |

### 阶段 2 贪心修复的航班选择机制

### 阶段 1（FATA）：不选择，全部同时优化

阶段 1 的核心特点是**不做"A vs B 选谁调"的决策**——FATA 将所有关键航班的延迟+速度编码为一个联合向量，由种群进化搜索全局最优：

```
假设 10 架关键航班: [99, 64, 62, 57, 83, 41, 51, 45, 19, 53]

FATA 个体向量 = [delay₉₉, delay₆₄, ..., delay₅₃, speed₉₉, speed₆₄, ..., speed₅₃]
                  ←── n 个延迟索引 ──→  ←── n 个速度索引 ──→
                         维度 = 2n = 20
```

**优化流程**：

```
FATA 种群（50 个个体）
    ├── 个体1: [d₉₉=+120, d₆₄=-60, ..., s₉₉=1.05, s₆₄=0.95, ...]
    ├── 个体2: [d₉₉=+60,  d₆₄=+30, ..., s₉₉=1.00, s₆₄=1.10, ...]
    └── ...
    │
    ▼ 每个个体 → 同时应用到所有关键航班 → 全局冲突检测 → 适应度
    │
    ▼ FATA 进化（光过滤 + 光传播）→ 200 代迭代 → 输出最优向量
```

**A 与 B 冲突时的处理**：

| 场景 | A 是关键航班？ | B 是关键航班？ | 阶段 1 行为 |
|------|:---:|:---:|------|
| 🅐 双方都是 | ✅ | ✅ | FATA 同时搜索 A 和 B 的延迟+速度，找到**联合最优** |
| 🅑 单方是 | ✅ | ❌ | 只优化 A，B 不动。冲突消解取决于 A 的调整效果 |
| 🅒 都不是 | ❌ | ❌ | 阶段 1 **完全不管**，留给阶段 2 处理 |

**关键代码**（`run_main.py` 第 155-170 行）：

```python
def objective(vec: np.ndarray) -> float:
    # vec 包含 ALL 关键航班的延迟+速度，一次性评估全局效果
    return evaluate_delay_speed_solution(vec, plans, key_ids, cfg, grid, risk).fitness

fata_res = fata_optimize(objective, lb, ub, dim=len(lb), population=50, max_iter=200)
stage1_plans = apply_delay_speed_vector(plans, key_ids, fata_res.best_position, ...)
```

> 📌 **核心区别**：阶段 1 是 $2n$ 维联合优化（$13^n \times 6^n$ 种组合），A 和 B 的变量在同一个解向量中共存，由种群进化找到全局最优配比，不存在选择问题。

### 阶段 2（贪心修复）：按冲突贡献排名逐个选择

```
剩余冲突列表
    │
    ▼
计算每架飞机的冲突贡献得分
    ├── 主排序键：涉及的冲突对数量（降序）
    └── 副排序键：涉及的冲突点数量（降序）
    │
    ▼
选得分最高的航班 → 尝试调整
    │
    ├── 成功（全局冲突减少）→ 接受，更新冲突列表
    └── 失败（全部候选动作 rollback）→ 标记为 stuck → 选下一架
```

### 关键代码位置

`src/optimization_model.py` → `_conflict_contribution()` + `greedy_time_deconfliction()`

### 核心特征

| 特征 | 说明 |
|------|------|
| 选择依据 | **全局冲突贡献排名**（冲突最多的航班优先） |
| 选择方式 | **确定性**（无随机因素，每次运行结果一致） |
| 判断标准 | `accept_only_if_global_conflicts_decrease = true` |
| 处理顺序 | **串行**（逐航班处理，非并发） |

## 第 2 点：错峰起飞与速度调整的统一调度方式

### 机制描述

阶段 1（FATA）和阶段 2（贪心修复）均采用**固定离散候选值**遍历策略：

| 策略 | 候选值 | 数量 |
|------|--------|:--:|
| 错峰起飞（delay） | [-180, -120, -90, -60, -30, 0, 30, 60, 90, 120, 180, 300, 600] 秒 | 13 档 |
| 速度调整（speed） | [0.90, 0.95, 1.00, 1.05, 1.10, 1.15] 倍速 | 6 档 |

### 阶段 1（FATA 全局优化）

- 将关键航班的延迟 + 速度编码为一个向量：`[delay₁, ..., delayₙ, speed₁, ..., speedₙ]`
- FATA 种群在离散候选索引空间中搜索
- 适应度 = $10^6 \times \text{冲突对} + 10^4 \times \text{冲突点} + \text{软成本}$

### 阶段 2（贪心修复）

```
对每架航班：
  for 延迟 in 13种候选值：
    评估全局冲突变化 → 记录得分
  for 速度 in 6种候选值：
    评估全局冲突变化 → 记录得分
  选 78 种组合中得分最高的动作
```

### 核心特征

| 特征 | 说明 |
|------|------|
| 候选值来源 | **固定预定义列表**（非连续搜索） |
| 延迟与速度关系 | **统一评估**，选最优组合 |
| 每航班尝试次数 | 最多 13（延迟）+ 6（速度）= **19 次/航班** |
| 接受条件 | 全局冲突对严格减少，或冲突对持平但软成本降低 |

## 第 3 点：4 个无法消解冲突的特征与原因

### 残留冲突详情

| # | 航班对 | 冲突栅格 | 高度层 | 实际间隔 | 所需间隔 | 缺口 |
|---|--------|----------|:---:|:------:|:------:|:---:|
| 1 | 4 ↔ 56 | (15, 26) | 2 | 9.9s | 72.9s | 63s |
| 2 | 14 ↔ 29 | (43, 25) | 1 | 32.8s | 70.3s | 38s |
| 3 | 16 ↔ 58 | (41, 16) | 1 | 37.2s | 80.7s | 43s |
| 4 | 45 ↔ 67 | (51, 31) | 1 | 30.0s | 94.6s | 65s |

### 共同特征

1. **全部为孤立单点冲突**——每对只有 1 个冲突点，非连续航段重叠
2. **冲突位于飞行中段**——非起飞/降落阶段
3. **时间缺口大**——实际间隔与所需间隔差距 38~65 秒
4. **涉事航班冲突网络重要性低**——8 架飞机中仅 1 架（45号）是关键航班
5. **空间分散**——4 个冲突点互不关联，消解互不影响

### 无法消解的原因链

```
单点冲突（缺口 38~65s）
    │
    ├── 尝试小调（±30s 延迟、±5% 变速）
    │       └── 缺口填不上 → 冲突仍在
    │
    └── 尝试大调（±60s+ 延迟、±10%+ 变速）
            └── 影响整条航线 → 产生新冲突
                    └── accept_only_if_global_conflicts_decrease = true
                            └── rollback → 放弃 → 保留冲突
```

### 具体证据

- **航班 16**：12 次调整全部 rollback（每次均导致全局冲突增加）
- **航班 14**：延迟成功将总冲突对从 61→59，但 14↔29 残留
- **航班 45**：已在阶段 1 被 FATA 优化过，后续调节空间极小
- **航班 4**：冲突发生在早期航路点（idx=5），延迟会拖慢全程

|------|:----:|
| 初始冲突 | 215 |
| 最终残留 | 4 |
| 消解率 | **98.1%** |
